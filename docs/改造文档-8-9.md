# 二、当前项目判断

GitHub 仓库当前 README 显示，该项目定位为 A 股低频语义关系层，支持 CSV fallback 和 NPY 多视图加载，输出 `semantic_feature_table`、`cluster_result`、`prototype_exposure`、`graph_stats`、`fused_graph.npz`、图表和日志等结果；主包结构包括 `core`、`data`、`features`、`graph`、`pipeline`、`tests`。([GitHub](https://github.com/789453/cluster-fundmental-stock-info-project "GitHub - 789453/cluster-fundmental-stock-info-project: cluster-fundmental-stock-info-project · GitHub"))

当前 `build_pipeline.py` 的主流程是：加载数据、校验列、构建语义视图特征、构建 anchor/quality 特征、融合特征、执行聚类、构建 kNN 图、融合多图、做图平滑、导出 Parquet/CSV/NPZ/Joblib 和基础图表。这个流程适合作为 demo 基座，但还没有接入真实 TuShare 日频行情、每日估值指标、财务指标、申万行业层级和 Barra 类风格暴露。([GitHub](https://github.com/789453/cluster-fundmental-stock-info-project/blob/main/a_share_semantic_engine/pipeline/build_pipeline.py "cluster-fundmental-stock-info-project/a_share_semantic_engine/pipeline/build_pipeline.py at main · 789453/cluster-fundmental-stock-info-project · GitHub"))

代码层面的主要短板很清楚：`clustering.py` 当前只用 `MiniBatchKMeans`，GPU 只用于距离计算示例；`knn_graph.py` 使用 sklearn `NearestNeighbors` 做 CPU cosine kNN；`smoothing.py` 在 GPU 分支把稀疏邻接矩阵 `toarray()` 变成 dense，这只适合小图；`export.py` 只绘制 cluster size 和 degree histogram，无法支撑研究报告级别的图网络诊断。([GitHub](https://github.com/789453/cluster-fundmental-stock-info-project/blob/main/a_share_semantic_engine/features/clustering.py "cluster-fundmental-stock-info-project/a_share_semantic_engine/features/clustering.py at main · 789453/cluster-fundmental-stock-info-project · GitHub"))

# 三、改造总目标

本项目应从“语义聚类 demo”升级为：

**A-share Semantic-Fundamental Graph Research Engine**

目标不是直接生成交易信号，而是构建后续策略、强化学习、组合优化、图因子、风险约束可以复用的研究底座。

1. **股票语义向量层**：1024 维语义向量，不再默认 PCA 降维。

# 七、图网络设计

## 7.1 多层图

构建五张基础图：

### 1. 语义相似图 `G_semantic`

节点：股票。

边权：

```
cosine(semantic_vector_i, semantic_vector_j)

```

要求：

- 1024 维直接计算。
- L2 normalize 后使用内积。
- 每个节点保留 top-k。
- 建议 k = 20 / 30 / 50 多配置。
- 使用 mutual kNN 降低噪声。
- 输出 edge rank。

FAISS 官方文档说明其用于高效相似搜索和密集向量聚类，并包含 GPU 实现，适合替换当前 sklearn CPU kNN。([Faiss](https://faiss.ai/index.html?utm_source=chatgpt.com "Welcome to Faiss Documentation — Faiss documentation"))

### 2. 申万行业层级图 `G_industry`

边权：

```
same_sw_l3: 1.00
same_sw_l2: 0.70
same_sw_l1: 0.40
otherwise: 0.00

```

可以额外加入行业中心节点：

```
stock -> sw_l3
sw_l3 -> sw_l2
sw_l2 -> sw_l1

```

形成异构图，便于后续图神经网络或图传播项目使用。

### 3. 基本面相似图 `G_fundamental`

输入特征：

```
profitability + growth + quality + leverage + valuation

```

边权：

```
cosine(zscore_fundamental_vector_i, zscore_fundamental_vector_j)

```

要求：

- 行业内和全市场各建一版。
- 财务数据按公告日 as-of。
- 缺失率过高的股票降低边权。

### 4. 收益相关图 `G_return_corr`

边权：

```
corr(ret_i, ret_j, rolling_window=60/120/252)

```

用途：

- 识别市场实际联动。
- 与语义图对比：语义相似但收益不联动，可能是潜在分化；收益联动但语义不相似，可能是风格/资金驱动。

### 5. 风格暴露图 `G_style`

边权：

```
exp(- ||style_i - style_j||_2 / tau)

```

用途：

- 区分语义相似和风格相似。
- 为后续组合优化提供拥挤度、风格集中度约束。

***

## 7.2 融合图

融合权重建议：

```
graph_fusion:
  semantic: 0.35
  industry: 0.20
  fundamental: 0.20
  return_corr: 0.15
  style: 0.10

```

边权：

```
W_fused =
  0.35 * W_semantic
+ 0.20 * W_industry
+ 0.20 * W_fundamental
+ 0.15 * W_return_corr
+ 0.10 * W_style

```

同时保留每类边权，不要只保存一个融合权重。后续策略、组合、强化学习项目需要知道关系来源。

4. 图中心节点是否代表行业龙头或主题核心资产。
5. 桥接节点是否更容易受到多主题轮动影响。
6. 簇内基本面分化是否预示未来收益分化。
7. 基本面相似但市场定价差异大的股票是否存在配对研究价值。

# 十二、性能优化方案

## 12.1 IO 优化

必须做到：

1. 只读需要的列。
2. 只读需要的日期区间。
3. 日频表按 `trade_date` 分区。
4. 财务表按 `ann_date` 或 `end_date` 分区。
5. 图和向量按 `trade_date + view` 分区。
6. 中间结果写 Parquet + ZSTD。
7. 大矩阵写 `.npy` memmap / Zarr，不塞进 CSV。
8. CSV 只作为小样本或人工检查输出。

DuckDB 文档说明 Parquet 的列式存储和统计信息可支持 projection/filter pushdown；这正适合本项目的大宽表和日期过滤场景。([DuckDB](https://duckdb.org/docs/lts/guides/performance/file_formats.html?utm_source=chatgpt.com "File Formats"))

***

## 12.2 计算优化

1. 语义向量统一 `float32`。
2. 使用矩阵乘法计算 cosine：`S = X @ X.T`，但大规模时只保留 top-k。
3. 使用 FAISS `IndexFlatIP` 做精确内积 kNN。
4. 历史多日批处理时，用增量计算：只重算新增交易日。
5. 特征标准化使用向量化，不逐股票循环。
6. rolling return / volatility 用 Polars 或 DuckDB window function。
7. 图统计优先用稀疏矩阵或 cuGraph。
8. 不再将图转 dense。

***

## 12.3 GPU 加速

推荐：

```
GPU tasks
- FAISS GPU: 1024 维语义 kNN
- cuGraph: Louvain / Leiden / PageRank
- PyTorch sparse: 图平滑
- CuPy: 大矩阵相似度、稀疏操作
- RAPIDS cuDF: 大规模 edge table 操作

```

替换当前实现：

```
sklearn NearestNeighbors
→ faiss.IndexFlatIP / faiss.GpuIndexFlatIP

MiniBatchKMeans
→ faiss.Kmeans 或 torch-kmeans

dense torch adjacency
→ torch sparse CSR / cuGraph Graph

pandas full read
→ DuckDB SQL / Polars LazyFrame

```

# 十六、最关键的改造原则

1. **不要把语义向量项目做成孤立 NLP demo。**\
   它必须与 TuShare 的行情、估值、财务和申万行业体系融合。
2. **不要直接上策略。**\
   本项目只输出研究特征、图结构、聚类结构、关系特征，为后续策略强化、组合优化、因子研究服务。
3. **不要默认 PCA。**\
   1024 维向量规模对 A 股横截面是可接受的，默认使用 float32 原维度计算。
4. **不要 dense graph。**\
   所有图使用 CSR/COO/edge table。
5. **不要只输出 cluster\_id。**\
   必须输出 cluster 的行业构成、风格暴露、财务画像、图中心性、稳定性和研究解释。
6. **不要忽略公告日。**\
   财务数据必须按 `ann_date <= trade_date` as-of join。
7. **不要只看语义相似。**\
   语义相似、基本面相似、行业相似、收益相关、风格相似要分开建图，再融合。
8. **不要让输出只适合看图。**\
   所有结果必须能被后续策略、RL、组合优化项目作为结构化输入直接消费。
