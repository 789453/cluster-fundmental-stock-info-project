# 一、当前项目状态与外部技术约束

项目 README 已声明它是面向 A 股研究的低频语义关系层项目，支持 CSV fallback、NPY + meta 多视图加载、多视图语义特征、kNN 图、聚类、图平滑、导出、日志、图表、checkpoint 和测试；README 还列出主输出包括 `semantic_feature_table`、`cluster_result`、`prototype_exposure`、`graph_stats`、`graphs/fused_graph.npz`、`reports/run_report.json` 和若干 figures。这个方向是对的，但目前实现没有真正把“图结构中间结果”和“后续绘图/研究分析”解耦成稳定契约。([GitHub](https://raw.githubusercontent.com/789453/cluster-fundmental-stock-info-project/upload-a-share-semantic/README.md "raw.githubusercontent.com"))

数据源方面，TuShare 的 `daily_basic` 官方文档说明它用于获取全市场股票每日重要基本面指标，包含交易日期维度，可用于选股分析；`fina_indicator` 官方文档说明它提供上市公司财务指标数据；申万行业成分分级接口 `index_member_all` 支持按三级分类或股票代码提取申万成分，这正好对应你希望使用的 `stock_daily_basic`、`stock_fina_indicator`、`stock_sw_member` 多源连续数据。([Tushare](https://tushare.pro/document/2?doc_id=32\&utm_source=chatgpt.com "总市值"))

存储层建议继续采用 DuckDB + Parquet。DuckDB 官方文档说明，查询 Parquet 时支持 projection pushdown，也就是只读取查询所需列；DuckDB Parquet tips 还说明它可以利用 row group metadata 做 predicate pushdown，只扫描满足 `WHERE` 条件的 row groups。因此，后续应该避免一上来 `pd.read_parquet` 全量读所有列，而应把“交易日、股票代码、字段集”的过滤尽量下推到 DuckDB SQL。([DuckDB](https://duckdb.org/docs/current/data/parquet/overview.html?utm_source=chatgpt.com "Reading and Writing Parquet Files"))

图结构保存建议统一为 SciPy CSR `.npz` + edge table Parquet。SciPy 官方 `save_npz` 文档说明它可保存 CSR/CSC/COO 等稀疏矩阵，默认支持压缩；`load_npz` 则用于把 `.npz` sparse matrix 加载回来。这个格式适合保存 5000 只股票、每只几十条边的稀疏图，比保存 dense `N×N` 相似度矩阵稳定很多。([SciPy 文档](https://docs.scipy.org/doc/scipy/reference/generated/scipy.sparse.save_npz.html?utm_source=chatgpt.com "save_npz — SciPy v1.17.0 Manual"))

kNN 搜索建议保留 FAISS 作为可选 GPU 后端。FAISS 官方说明它是面向 dense vectors 的高效相似度搜索和聚类库，包含 GPU 实现；FAISS GPU 文档还说明 GPU 版本通常相对 CPU 有显著加速。结合项目中 1024 维股票语义向量，不建议做 PCA 作为默认前置步骤，而应直接对 `float32`、L2-normalized 的 1024 维矩阵建立 inner-product kNN。([Faiss](https://faiss.ai/index.html?utm_source=chatgpt.com "Welcome to Faiss Documentation — Faiss documentation"))

社区发现方面，Leiden 比 Louvain 更适合作为后续图聚类主路线。`leidenalg` 文档说明它是 C++ 实现并暴露 Python 接口，依赖 igraph，支持大规模图；其介绍页也说明它用于网络 community detection。当前项目可保留 k-means 作为语义向量聚类基线，但图结构研究应优先支持 Leiden/Louvain，并把两类标签同时保存，便于比较“语义空间簇”和“图社区”。([Leidenalg 文档](https://leidenalg.readthedocs.io/en/stable/reference.html?utm_source=chatgpt.com "Reference - leidenalg documentation"))

# 二、核心目标：把项目改成“可恢复、可复算、可绘图、可研究”的分阶段系统

建议把项目升级目标定义为：

第一，所有阶段输出都必须可独立保存、可独立加载、可校验 schema。不能只保存最终报告，也不能只在内存里传递 `graphs` 字典。

第二，图结构必须至少保存三类结果：`CSR adjacency`、`edge table`、`graph metadata`。CSR 用于后续图算法，edge table 用于绘图、解释、导出和审计，metadata 用于记录图来源、参数、边数、平均度、孤立点数量、权重分布。

第三，绘图分析必须作为独立阶段，从已保存结果读取，不重新构图。即 `stage9_visualization` 只能依赖 `stage1_snapshot/stage4_graphs/stage5_fusion/stage6_clustering/stage7_graph_metrics/stage8_report` 的落盘文件。

第四，连续数据必须在 snapshot 之前或 snapshot 过程中构建成稳定的 panel feature。当前单日 snapshot 不足以支撑动量、反转、波动率、收益相关图、Beta 等特征。

第五，测试要覆盖“冷启动完整跑”“中断后从缓存恢复”“只跑绘图”“合成小数据无本地 DuckDB 也可跑”“图保存后 reload 等价”五类场景。现在测试中大量依赖硬编码 Windows 本地路径 `D:\Trading\data_ever_26_3_14\data\meta\warehouse.duckdb`，这会让 CI 或他人环境直接 skip，无法暴露真实 bug。测试目录和该硬编码路径可在 `test_staged_pipeline.py` 中看到。([GitHub](https://raw.githubusercontent.com/789453/cluster-fundmental-stock-info-project/upload-a-share-semantic/a_share_semantic_engine/tests/test_staged_pipeline.py "raw.githubusercontent.com"))

# 三、逐文件问题诊断与修改方案

## 1. `a_share_semantic_engine/pipeline/staged_pipeline.py`

这是当前最重要的文件。它已经定义了 `Stage`、`SnapshotStage`、`BarraStage`、`SemanticStage`、`GraphBuilderStage`、`GraphFusionStage`、`ClusteringStage`、`GraphMetricsStage`、`ReportStage` 和 `run_staged_pipeline`，说明项目已经有了分阶段缓存的雏形。问题是缓存协议和阶段输入输出还没有真正闭环。([GitHub](https://raw.githubusercontent.com/789453/cluster-fundmental-stock-info-project/upload-a-share-semantic/a_share_semantic_engine/pipeline/staged_pipeline.py "raw.githubusercontent.com"))

### 问题 1：`Stage.load_cached()` 没有加载 `.npz` 稀疏图

当前 `_save()` 已经能对 `sparse.csr_matrix` 调用 `sparse.save_npz` 保存，但 `load_cached()` 只扫描 `.npy`、`.parquet`、`.csv`，没有扫描 `.npz`。后果是：第一次完整运行可能成功，第二次 resume 或 `start_from_stage > 1` 时，`stage4_graphs` 或 `stage5_fusion` 的 CSR 图虽然在磁盘存在，但加载回来的 `data` 里没有 `graph_semantic`、`graph_industry`、`fused_csr`，后续阶段会出现 key error 或空图。

**修改要求：**

在 `Stage.load_cached()` 中加入：

```
for f in self.stage_dir.glob("*.npz"):
    data[f.stem] = sparse.load_npz(str(f)).tocsr()

```

然后对 `GraphBuilderStage` 单独恢复：

```
if self.name == "graph_builder":
    graphs = {}
    for key, val in data.items():
        if key.startswith("graph_") and sparse.issparse(val):
            graphs[key.replace("graph_", "", 1)] = val.tocsr()
    if graphs:
        data["graphs"] = graphs

```

对 `GraphFusionStage` 单独恢复：

```
if self.name == "fusion" and "fused_csr" in data:
    data["fused_csr"] = data["fused_csr"].tocsr()

```

### 问题 2：`Stage._save()` 对 dict/list 没有通用保存逻辑

当前 `_save()` 只处理 ndarray、DataFrame、CSR、numpy scalar、基础类型；`manifest` 作为 dict 传入时不会被完整保存。虽然 `_save()` 会生成自己的 `manifest.json`，但阶段输出里的业务 manifest，比如 `graphs` 列表、参数、coverage、列名、hash 等，不应该丢失。建议增加 `dict/list/tuple` 的 JSON 保存。

```
elif isinstance(val, (dict, list, tuple)):
    p = self.stage_dir / f"{key}.json"
    p.write_text(json.dumps(val, ensure_ascii=False, indent=2, default=str), encoding="utf-8")
    manifest[f"{key}.json"] = str(p)

```

同时 `load_cached()` 加载 JSON：

```
for f in self.stage_dir.glob("*.json"):
    if f.name == "manifest.json":
        continue
    data[f.stem] = json.loads(f.read_text(encoding="utf-8"))

```

### 问题 3：`SemanticStage.run()` 与 `VectorStore.load_view()` 返回值不匹配

`graph_builder.py` 中 `VectorStore.load_view()` 返回 `(vectors, row_ids, stock_codes)` 三个对象；但 `SemanticStage.run()` 中使用 `vectors, row_ids = vs.load_view(v)`，这会直接触发 `ValueError: too many values to unpack`。同文件的 `VectorStore.validate_alignment()` 也写成 `_, row_ids = self.load_view(view)`，同样不匹配。([GitHub](https://raw.githubusercontent.com/789453/cluster-fundmental-stock-info-project/upload-a-share-semantic/a_share_semantic_engine/graph/graph_builder.py "raw.githubusercontent.com"))

**修改要求：**

`SemanticStage.run()` 改为：

```
vectors, row_ids, stock_codes = vs.load_view(v)
idx_map = vs.get_index(v, ts_codes)

```

`VectorStore.validate_alignment()` 改为：

```
_, row_ids, stock_codes = self.load_view(view)
key_set = set(row_ids) | set(stock_codes)
matched = sum(1 for c in ts_codes if c in key_set)
return matched / len(ts_codes) if ts_codes else 0.0

```

### 问题 4：向量对齐策略过于冒险

现在 `SemanticStage` 如果 `idx_map` 不是完整长度，就退化为 `vectors[:len(ts_codes)]`。这是严重研究风险：一旦语义向量排序和 snapshot 股票排序不一致，后续所有图边都错配，图看起来能跑但研究结论错误。

**修改要求：**

只允许三种模式：

1. `strict`：覆盖率低于阈值直接失败。
2. `hybrid`：已匹配股票使用语义向量，未匹配股票使用数值 fallback 向量并记录 `semantic_coverage`。
3. `fallback`：完全不用 NPY，使用 snapshot 数值特征。

新增参数：

```
semantic:
  alignment_mode: hybrid
  min_coverage: 0.95
  fallback_numeric_cols:
    - total_mv
    - pe_ttm
    - pb
    - roe
    - turnover_rate
    - ret_20d
    - realized_vol_60d

```

保存：

```
stage3_semantic/
  feat_matrix.npy
  semantic_alignment.parquet
  manifest.json

```

`semantic_alignment.parquet` 字段包括：

```
ts_code, record_id, vector_index, matched, source_view, fallback_used

```

### 问题 5：`GraphBuilderStage` 的收益相关图输入方向错误

### 问题 7：`GraphFusionStage` 先把 CSR 转 kNN，再构造 dense `fused_sim`

当前 `fuse_multiplex_graphs()` 会创建 `N×N` dense float32 矩阵。5000 股票时单个 dense 矩阵约 100MB，多个阶段叠加还可以接受；但后续如果做多日期 panel 或扩大候选资产池，很快会放大 IO 和内存。更重要的是，图本来就是稀疏结构，不应该反复 dense 化。

**修改要求：**

新增 `a_share_semantic_engine/graph/fusion.py`：

```
def fuse_sparse_graphs(
    graphs: dict[str, sparse.csr_matrix],
    weights: dict[str, float],
    normalize: Literal["max", "row_sum", "none"] = "max",
    topk: int = 50,
    min_weight: float = 1e-6,
) -> sparse.csr_matrix:
    """
    Sparse weighted sum + per-row topk pruning.
    """

```

逻辑：

1. 每个图先去自环、转 CSR。
2. 每个图按 `data.max()` 或 row sum 归一化。
3. `fused = sum(w_i * graph_i) / sum(w_i)`
4. 对每行只保留 topk。
5. 对称化：`fused = fused.maximum(fused.T)`
6. 去自环：`fused.setdiag(0); fused.eliminate_zeros()`

`GraphFusionStage.run()` 不再调用 `fuse_multiplex_graphs()`，而是直接处理 CSR dict。

### 问题 8：`run_staged_pipeline(start_from_stage=...)` 不能正确补齐前置缓存

当前循环从 `STAGE_CLASSES[max(0, start_from_stage - 1):]` 开始。假设用户从 Stage 7 开始，`stage_data` 是空的；代码不会自动加载 Stage 1 到 Stage 6 的缓存，Stage 7 必然缺输入。

修改为先加载所有前置阶段缓存：

    stage = stage_cls(output_dir)
    cached = stage.load_cached()
    if cached is None:
        raise FileNotFoundError(f"Required cache missing for previous stage: {stage.name}")

```

然后再运行目标阶段之后的阶段。新增测试 `test_resume_from_each_stage()`，逐个 `start_from_stage=2..9` 跑一遍。

## 2. `a_share_semantic_engine/graph/graph_builder.py`

这个文件负责向量加载、语义 kNN、行业图、基本面图、收益相关图、风格图、融合和 CSR 构造。它是性能瓶颈，也是错边风险最大的位置。([GitHub](https://raw.githubusercontent.com/789453/cluster-fundmental-stock-info-project/upload-a-share-semantic/a_share_semantic_engine/graph/graph_builder.py "raw.githubusercontent.com"))

### 问题 1：`VectorStore.get_index()` 对部分匹配返回不完整索引

现在 `indices = [key_to_idx[k] for k in keys if k in key_to_idx]` 会丢掉未匹配股票，并且返回长度小于 `ts_codes` 的数组。上游如果只检查长度，很容易走错 fallback。更好的接口应该返回固定长度数组，未匹配为 `-1`。

```
def get_index(self, view: str, keys: list[str]) -> np.ndarray:
    _, row_ids, stock_codes = self.load_view(view)
    key_to_idx = {}
    key_to_idx.update({rid: i for i, rid in enumerate(row_ids) if rid})
    key_to_idx.update({code: i for i, code in enumerate(stock_codes) if code})
    return np.array([key_to_idx.get(k, -1) for k in keys], dtype=np.int64)

```

### 问题 2：FAISS mutual kNN 的候选索引逻辑可能越界

`_faiss_knn()` mutual 分支中，`candidates = np.where(m)[0]` 是原始股票节点 id，但后续使用 `sims[i, :k][candidates]`，这里 `sims[i, :k]` 长度只有 k，如果 candidate id 大于 k 就会越界或取错。应建立 `neighbor_id -> similarity` 字典。

```
sim_map = {int(idxs[i, j]): float(sims[i, j]) for j in range(k)}
candidate_sims = np.array([sim_map.get(int(c), 0.0) for c in candidates], dtype=np.float32)

```

### 问题 3：`build_industry_graph()` 是 O(N²) dense 构造

当前函数对所有股票两两比较申万 L1/L2/L3，先构造 dense `adj = np.zeros((N, N))`。全市场 5000 股票时约 2500 万 pair；多日期运行时非常慢。行业图天然适合按 group 构造，不需要两两全比较。

建议重写为：

```
def build_industry_graph_sparse(
    ts_codes: list[str],
    l1: Sequence[str],
    l2: Sequence[str],
    l3: Sequence[str],
    max_neighbors_per_level: dict[str, int] = {"l1": 15, "l2": 25, "l3": 40},
) -> sparse.csr_matrix:

```

逻辑是按 L3、L2、L1 group 分桶，同组内按市值接近、语义接近或随机稳定采样选 topk，避免大行业形成超级 dense clique。权重建议：

```
same_l3 = 1.00
same_l2 = 0.70
same_l1 = 0.40

```

### 问题 4：`build_csr_from_knn()` 没有过滤 0 权重和自环

当前 padded neighbor 默认是 0，如果 `data=0` 没过滤，CSR 中可能出现大量 0 存储或自环边。建议：

```
mask = (
    (cols >= 0) &
    (cols < N) &
    (rows != cols) &
    np.isfinite(data) &
    (data > eps)
)
csr = sparse.csr_matrix((data[mask], (rows[mask], cols[mask])), shape=(N, N))
csr = csr.maximum(csr.T)
csr.setdiag(0)
csr.eliminate_zeros()

```

### 问题 5：基本面图和风格图应该支持 GPU/批量 topk

`build_fundamental_graph()` 和 `build_style_graph()` 当前都可能构造 dense `N×N` 或 `N×N×D`。风格图里的 `diff = style_vectors[:, None, :] - style_vectors[None, :, :]` 对 N=5000、D=12 虽还能跑，但内存浪费。建议统一用 `build_knn_from_matrix()`：

```
def build_knn_from_matrix(
    X: np.ndarray,
    k: int,
    metric: Literal["cosine", "l2", "ip"],
    backend: Literal["faiss_gpu", "faiss_cpu", "sklearn", "exact"],
    batch_size: int = 4096,
) -> tuple[np.ndarray, np.ndarray, np.ndarray]:

```

## 3. `a_share_semantic_engine/data/snapshot_builder.py`

## 4. `a_share_semantic_engine/features/barra_style.py`

这个文件当前文档写得比实现更完整，存在“定义与代码不一致”的问题。文档中写 Size 是 `zscore(log(total_mv))`，Momentum 是 `ret_252d - ret_20d`，ShortReversal 是 `-ret_20d`，Value 是估值类组合；但当前实现里 Size 直接对 `total_mv` 均值化，Value 直接平均 `pb/pe_ttm/ps_ttm/dv_ratio`，ShortReversal 直接用 `ret_20d`，NonlinearSize 也不是残差。([GitHub](https://raw.githubusercontent.com/789453/cluster-fundmental-stock-info-project/upload-a-share-semantic/a_share_semantic_engine/features/barra_style.py "raw.githubusercontent.com"))

建议把 Barra 风格暴露改为显式函数，避免混在一个大循环里：

```
def compute_size(df):
    return zscore(np.log(df["total_mv"].clip(lower=1.0)))

def compute_value(df):
    inv_pb = 1.0 / df["pb"].replace(0, np.nan)
    inv_pe = 1.0 / df["pe_ttm"].replace(0, np.nan)
    inv_ps = 1.0 / df["ps_ttm"].replace(0, np.nan)
    dividend = df["dv_ratio"]
    return zscore(pd.concat([zscore(inv_pb), zscore(inv_pe), zscore(inv_ps), zscore(dividend)], axis=1).mean(axis=1))

def compute_short_reversal(df):
    return zscore(-df["ret_20d"])

```

NonlinearSize 应回归：

```
size = compute_size(df)
x = np.column_stack([np.ones(len(size)), size.values, size.values ** 2])
beta = np.linalg.lstsq(x, size.values, rcond=None)[0]
resid = size.values - x @ beta

```

更合理的是把原始暴露、winsorized 暴露、行业中性暴露全部保存：

```
Size_raw, Size_z, Size_sw_neutral
Value_raw, Value_z, Value_sw_neutral
...

```

这样后续研究能区分“原始特征”和“行业中性后的风格暴露”。

## 5. `a_share_semantic_engine/features/clustering.py`

这个文件支持 kmeans、hdbscan、leiden、louvain、modularity、NMI、purity。实现方向是好的，但图聚类部分仍有细节风险。([GitHub](https://raw.githubusercontent.com/789453/cluster-fundmental-stock-info-project/upload-a-share-semantic/a_share_semantic_engine/features/clustering.py "raw.githubusercontent.com"))

### 问题 1：`run_leiden()` 权重提取逻辑不稳

当前：

```
weights = adj[sources, targets].A1 if hasattr(adj, "A") else np.ones(len(sources))

```

这里判断的是 `adj` 是否有属性 `A`，而不是切片结果是否可转数组。更稳写法：

```
weights = np.asarray(adj[sources, targets]).ravel().astype(np.float32)

```

此外，CSR 对称图会有双向边，igraph 无向图里重复边可能导致权重重复。建议只取 `sources < targets`：

```
mask = sources < targets
edges = list(zip(sources[mask].tolist(), targets[mask].tolist()))
weights = weights[mask].tolist()

```

### 问题 2：HDBSCAN 的 `-1` 噪声标签没有统一处理

`ClusteringStage.validate()` 当前要求所有 `cluster_id >= 0`，这会导致 HDBSCAN 合法噪声点报错。建议：

```
allow_noise = method == "hdbscan"
if not allow_noise:
    assert (cluster_df["cluster_id"] >= 0).all()

```

报告阶段统计：

```
n_noise, noise_ratio, n_effective_clusters

```

### 问题 3：聚类结果没有分层保存

建议保存三份：

```

  cluster_labels.parquet
  cluster_centroids.npy
  cluster_membership.parquet

`cluster_labels.parquet`：

```

```

Scikit-learn 官方说明它提供 clustering 等机器学习工具；这里使用 silhouette、Davies-Bouldin、Calinski-Harabasz 作为聚类质量诊断是合适的，但不能只存在 report JSON 里，必须落盘成独立质量文件。([Scikit-learn](https://scikit-learn.org/?utm_source=chatgpt.com "scikit-learn: machine learning in Python — scikit-learn 1.8.0 ..."))

## 6. `a_share_semantic_engine/graph/graph_metrics.py`

这个文件已经计算 degree、pagerank、eigenvector centrality、betweenness、clustering coefficient、k-core、bridge score、邻居聚合等指标。方向正确，但部分实现有数学和性能问题。([GitHub](https://raw.githubusercontent.com/789453/cluster-fundmental-stock-info-project/upload-a-share-semantic/a_share_semantic_engine/graph/graph_metrics.py "raw.githubusercontent.com"))

### 问题 1：degree 被重复累计

当前代码对 `sources` 和 `targets` 都 `np.add.at`，如果 `adj` 已经是对称矩阵，那么每条边在 `.nonzero()` 里已经出现两次，再对 target 加一次会导致 degree 近似翻倍。应改为：

```
weighted_degree = np.asarray(adj.sum(axis=1)).ravel().astype(np.float32)
metrics["degree"] = weighted_degree
metrics["unweighted_degree"] = np.diff(adj.indptr).astype(np.int32)

```

### 问题 2：`_pagerank()` 可能原地改动输入矩阵

`P = adj.tocsr()` 不应假设总是深拷贝。应写：

```
P = adj.astype(np.float64).copy().tocsr()

```

并处理 dangling nodes。NetworkX 官方 PageRank 文档说明 PageRank 根据图的链接结构对节点进行排序；本项目里的股票 PageRank 可以解释为“关系网络中的结构中心股票”，但要确保计算没有改变原图。([NetworkX](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.link_analysis.pagerank_alg.pagerank.html?utm_source=chatgpt.com "pagerank — NetworkX 3.6.1 documentation"))

### 问题 3：`_betweenness_approx()` 不是标准 betweenness

NetworkX 官方 betweenness centrality 定义为经过某节点的最短路径占比，并支持用 `k` 个 pivot 做近似；当前实现只是 BFS parent path 的粗略计数，不能命名为 betweenness。建议改成：

```
def _betweenness_approx(adj, n_samples=200):
    import networkx as nx
    G = nx.from_scipy_sparse_array(adj, edge_attribute="weight")
    return np.array([
        nx.betweenness_centrality(G, k=n_samples, weight=None, seed=42).get(i, 0.0)
        for i in range(adj.shape[0])
    ], dtype=np.float32)

```

或者改名为 `bfs_bridge_proxy`，避免研究报告误导。([NetworkX](https://networkx.org/documentation/stable/reference/algorithms/generated/networkx.algorithms.centrality.betweenness_centrality.html?utm_source=chatgpt.com "betweenness_centrality — NetworkX 3.6.1 documentation"))

### 问题 4：k-core 应使用无权 degree

`_kcore()` 当前把 `adj.sum(axis=1)` 转成 int，等于把权重 degree 截断后做 k-core。更稳方案：

```
A_bin = adj.copy()
A_bin.data[:] = 1
G = nx.from_scipy_sparse_array(A_bin)
core = nx.core_number(G)

```

# 十、推荐的实施顺序

第二天做 P1：统一图保存和 edge table。跑完后必须能在磁盘看到每一类图的 CSR 和 parquet 边表。

第三天做 P2：接入连续行情 panel，补齐 ret、vol、momentum、beta，修 Barra 定义。

第四天做 P3：稀疏图融合、行业图 sparse 构造、统一 kNN backend。

第五天做 P4/P5：报告和绘图只读 artifacts，输出研究图和 HTML 网络图。

第六天补测试和文档，把所有命令固化：

```
python -m a_share_semantic_engine.cli staged \
  --trade-date 20260423 \
  --config configs/base.yaml \
  --cluster-method leiden \
  --use-cuda

```

```
python -m a_share_semantic_engine.cli visualize \
  --run-dir outputs/20260423/latest

```

```
pytest -q a_share_semantic_engine/tests \
  -k "cache or graph or resume or alignment or visualization"

```

整体上，这个项目已经具备成为“语义基本面图网络研究底座”的基础，但必须从“能一次性跑出结果”升级为“中间结果可审计、图结构可复用、连续数据可解释、绘图与计算解耦、测试可复现”的工程系统。完成上述改造后，它才能稳定服务后续的策略强化、组合优化、风格约束、行业中性和因子研究项目。
